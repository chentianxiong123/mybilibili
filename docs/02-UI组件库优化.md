# UI 组件库优化：Element Plus 瘦身

## 问题

Element Plus 是当前项目体积最大的单一依赖。

| 指标 | 数值 |
|------|------|
| 组件使用数 | 50 个 |
| 总 CSS 体积 | 183 KB |
| 总 JS 体积 | 捆绑在入口 chunk 中 |
| 初始 CSS | 98 KB（含 Element Plus 变量 + 常用组件样式） |

## 优化策略

### 1. 按需导入（已实施）

使用 `unplugin-vue-components` + `unplugin-auto-import` 实现自动按需加载，避免全量注册。

```typescript
// vite.config.ts
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default {
  plugins: [
    AutoImport({
      resolvers: [ElementPlusResolver()]
    }),
    Components({
      resolvers: [ElementPlusResolver({ importStyle: 'css' })]
    }),
  ]
}
```

**效果：** 只导入模板中实际使用的组件，未使用的组件不会进入打包。

### 2. 版本升级（2.7.5 → 2.14.4）

升级到最新稳定版，获得最新的体积优化和修复。

```bash
pnpm add element-plus@2.14.4
```

### 3. CSS 按需拆分

每个 Element Plus 组件的 CSS 被拆分为独立文件，按路由加载。

| CSS 文件 | 大小 | 加载时机 |
|----------|------|---------|
| el-divider | 37K | 主入口（含网格系统） |
| el-date-picker | 29K | 数据编辑页面 |
| el-table-column | 20K | 管理后台 |
| el-tab-pane | 16K | 管理后台 |
| el-upload | 12K | 上传页面 |

### 4. LightningCSS 压缩

使用 LightningCSS 替代 esbuild 进行 CSS 压缩，获得更好的压缩率。

```typescript
build: {
  cssMinify: 'lightningcss'
}
```

## 后续可选方案

### 方案 A：保守路线（保持 Element Plus）

使用 `@element-plus/nuxt` 模块，在 Nuxt 中继续使用 Element Plus，标签不变，迁移成本最低。

### 方案 B：推荐路线（迁移到 @nuxt/ui）

| 对比 | Element Plus | @nuxt/ui |
|------|-------------|----------|
| 组件数 | 50 | 125+ |
| CSS 体积 | 183 KB | ~5 KB（Tailwind 按需） |
| SSR 兼容 | 需 `<ClientOnly>` | 原生支持 |
| 主题系统 | CSS 变量覆盖 | Tailwind 配置 |
| 基础组件 | Radix Vue（无样式） | 内置样式 |

### 方案 C：极致路线（shadcn-vue）

复制粘贴模式，零库依赖，完全控制代码，但需要手动维护。

## 原则

- UI 组件库的优化核心是 **"只用你需要的"**
- 按需导入 + CSS 拆分 + 压缩，三步走完基本够用
- 真正的大幅优化需要换库，但需要权衡迁移成本
