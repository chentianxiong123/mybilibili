# 三 Agent 并行开发协作方案

> 更新：2026-09-27（第三次 auth 修复后）
>
> 背景：一个人串行修 bug 太慢。现在把项目拆成三个并行领域，每个领域
> 由一个 agent 长期值守：**web / wap / admin**。本文档定义边界、规则、验收，
> 是三个 agent 都该读的第一份文件。

## 一、分工与领地（谁动哪些目录）

| 角色 | 领域 | 拥有目录（只准改这些） | 跑什么测试 |
|---|---|---|---|
| **web agent** | 桌面 Web 用户端（Nuxt SSR） | `web/user/**` | `bash scripts/test.sh frontend`（web/user vitest）+ 相关 backend 测试 |
| **wap agent** | 移动 H5（Vite + Vue3） | `mobile/wap/**` | `bash scripts/test.sh e2e`（`tests/e2e/wap/**`）|
| **admin agent** | 管理后台（Vite SPA） | `web/admin/**` | `bash scripts/test.sh frontend`（web/admin vitest）+ 打 admin API 的手测 |

**共享但没人独占**（改了要先认领、只动自己需要的部分、不碰别人的逻辑）：
- `services/**`、`shared/**` —— Go 后端
- `tests/**`、`contracts/**`、`scripts/test.sh`、`dev/docker-compose.yml`
- `sql/**`（数据库迁移）

## 二、git 协作规则（三条铁律）

1. **只 stage 自己领地内的文件**。`git add` 前先 `git status`，绝不用 `git add .`。
   `web/user`、`mobile/wap`、`web/admin` 三个前端互不相交，误 stage 别人的改动 = 冲突。
2. **不要碰这两类未跟踪文件**：`.air/work.toml`（另一套环境生成）、
   `external/cf-whisper-worker/.wrangler/**`（worker 本地缓存）。
3. 提交信息用既有风格：`fix(scope): 中文一句话`，scope 用 `wap`/`web`/`admin`/
   `auth`/`search` 等。改完跑**自己领地**的测试，全绿再提交，然后 `git push origin main`。

## 三、跨领域的坑（三个 agent 都要知道的全局事实）

- **后端是 source of truth，前端适配后端**。前端字段一律按后端返回的
  snake_case 接，或在前端做显式换算；绝不能假设后端给你 camelCase。
- **后端改了要等 air 自动 rebuild**（容器里 PID 1 是 air，watch `*.go|*.toml`），
  不用手动 `docker compose up -d --build`；改完等 ~3 秒再测。
- **Go 鉴权只有两道闸**：`auth.AdminPathGuard`（管理口）+ handler 内
  `httputil.RequireUser`（自助端点）。新增管理端点→加进
  `shared/pkg/auth/require_admin.go` 的 `adminOnlyPrefixes`；新增用户自助端点→
  handler 里 `RequireUser`。两个入口都要，别漏。
- **登录凭证是 HttpOnly Cookie**（`token`/`refresh_token`/`user_info`），
  前端读不到 token，只能靠 localStorage 里的展示信息判断登录态。

## 五、验收门禁（三个 agent 共同遵守）

合并进 main 前：
1. 自己领域测试全绿（上面表格的列）
2. `scripts/test.sh backend`、`contract`、`e2e` 至少跑一次确认没把别人领域搞坏
3. 改了 Go → gofmt 自己的文件；`gofmt -l` 报出**别人**的文件不算你的错，别顺手改

## 六、如果你要开新问题

- 想动别人领地的文件 → 先在聊天里说清楚，达成一致再动
- 后端 bug 无论谁发现的都能修，但改完跑全套 backend 测试
- 文档更新 → `docs/agents/` 下各自更新自己的文档，别跨文档乱改
