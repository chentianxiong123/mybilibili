# 构建与部署优化

## 构建工具链优化

### 1. LightningCSS 替代 esbuild

Vite 6 默认使用 esbuild 进行 CSS 压缩。LightningCSS 提供更好的压缩率。

```typescript
// vite.config.ts
build: {
  cssMinify: 'lightningcss' // 替代默认的 esbuild
}
```

需要安装：

```bash
pnpm add -D lightningcss
```

### 2. Brotli 预压缩

动态压缩消耗 CPU，预编译 `.br` 文件在构建时生成，Nginx/Traefik 直接返回。

```typescript
import viteCompression from 'vite-plugin-compression'

// vite.config.ts
plugins: [
  viteCompression({
    algorithm: 'brotliCompress',
    ext: '.br',
    threshold: 1024,       // 仅压缩 > 1KB 的文件
    deleteOriginalAssets: false  // 保留原始文件
  })
]
```

**效果对比：**

| 文件 | 原始 | gzip | brotli |
|------|------|------|--------|
| 主入口 JS | 295K | 96K | **81K** |
| vendor-vue | 111K | 43K | **39K** |
| 初始 CSS | 97K | 14K | **12K** |
| 总计 | 503K | 170K | **158K** |

### 3. Deploy 层压缩

在 Traefik 中配置 Brotli/Gzip 压缩中间件，作为兜底。

```yaml
# Traefik 动态配置
http:
  middlewares:
    compress:
      compress:
        excludedContentTypes:
          - text/event-stream  # 排除 SSE
```

## 部署架构优化

### 当前架构（CSR）

```
Nginx → 静态文件（Vite 构建产物）
      → Go 后端（API）
```

### 目标架构（SSR）

```
Nginx → Nuxt SSR 服务器
      → Go 后端（API，不变）
      → 静态资源（CDN）
```

## PWA 离线缓存

使用 `vite-plugin-pwa` 实现 Service Worker 预缓存，二次访问近乎即时加载。

```typescript
VitePWA({
  registerType: 'autoUpdate',
  workbox: {
    globPatterns: ['**/*.{js,css,html,svg,png,jpg,ico,woff2}'],
  },
  manifest: {
    name: '哔哩哔哩',
    display: 'standalone',
    theme_color: '#fb7299'
  }
})
```

**效果：** 192 个资源被预缓存，总计 3.6 MB，二次访问零网络请求。

## 构建性能优化

| 优化项 | 效果 |
|--------|------|
| LightningCSS | 构建速度提升 2-3x（相比 esbuild） |
| Brotli 预压缩 | 运行时零 CPU 消耗 |
| PWA 预缓存 | 用户二次访问零等待 |
| 多阶段构建 | 生产镜像仅 ~64MB |

## 最佳实践

1. **构建时压缩**：Brotli 预压缩优于动态压缩
2. **缓存策略**：区分 chunk 版本号，长缓存第三方库
3. **CDN 分发**：静态资源托管到 CDN，减少源站压力
4. **PWA 回退**：离线时也能展示基本内容
