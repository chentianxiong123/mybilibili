# 浏览器缩放冻结布局方案

> 目标：浏览器缩放时布局保持"冻结不重排"，组件位置/高度不回归。适用于以固定设计稿宽度（1440px）为核心的桌面端页面。

## 1. 背景与问题

桌面端页面布局基于固定宽度设计（`1440px`），默认使用流式布局。用户缩放浏览器（`Ctrl +/-`）时，`window.innerWidth` 会随缩放反向变化：

- 放大时 `innerWidth` 变小，布局重新排列（栅格收缩、换行、错位）；
- 放大 > 150% 后布局明显错乱，视频区与头部/导航重叠、列宽变化。

需求目标（方案 A）：**超过阈值（约 150%）后，继续放大 = 纯放大 + 横向滚动，布局不再重排**；低于阈值时保持正常流式自适应。

## 2. 技术原理

浏览器缩放改变的是"一个 CSS px 对应的设备像素数"，反应为 `window.innerWidth` 反比变化，而 `window.outerWidth`（窗口 CSS 宽）不变。因此可以用两者比值得到真实缩放比：

```
zoom = window.outerWidth / window.innerWidth
```

- zoom = 1.0 → 100%；zoom = 1.5 → 150%；zoom = 0.5 → 50%（缩小）。

冻结策略：把页面根元素的最小宽度锁在某个基准值（`--zoom-base`），当实际可用宽度小于该基准时，浏览器不再压缩页面而是产生横向滚动，从而实现"放大后不重排、纯放大 + 横向滚动"。

## 3. 实现一（初版，存在缺陷）

### 全局 CSS：根元素最小宽度

```css
html, body {
  min-width: var(--zoom-base, 1440px);
}
```

### JS：同步缩放基准

```javascript
const ZOOM_FREEZE_RATIO = 1.5

const syncZoomBase = () => {
  const root = document.documentElement
  const current = window.innerWidth
  const base = parseFloat(root.style.getPropertyValue('--zoom-base')) || 0
  const target = Math.floor(current / ZOOM_FREEZE_RATIO)
  if (target > base) {
    root.style.setProperty('--zoom-base', `${target}px`)
  }
}
```

在 `onMounted` 初始化并监听 `resize`：

```javascript
onMounted(() => {
  syncZoomBase()
  window.addEventListener('resize', syncZoomBase)
})
```

### 布局配合

- header 使用 `position: sticky; top: 0; width: 100%`（**不可用 fixed**，fixed 会随视口压缩）；
- home 布局把 header 放首位，`.home-hero { margin-top: -80px }` 拉回 hero，保持原"悬浮在渐变顶部"的视觉效果；
- 删除全部 ≤1400px 的媒体查询断点（共 86 块），仅保留 1920/2200/2560，确保缩放时列宽不变。

### 缺陷表现

`syncZoomBase` 中 `if (target > base)` 是一个**单向递增闸门**：`--zoom-base` 只会变大、永不回落。加上 `target = current / 1.5` 的 1.5 因子，导致：

1. **过度缩小把 base 撑爆**：50% 缩小时 `innerWidth = 2880px` → `target = 1920px` → base 被写成 1920px，远超真实视口；
2. **再次放大即触发冻结且无法居中**：回到 100% 时 `innerWidth = 1440` → `target = 960`，`960 > 1920` 为 false，base 永远停在 1920px。`min-width: 1920px` 压在 1440px 视口上 → 立即冻结、内容超出屏幕、无法居中、带横向滚动；
3. 阈值本质是"base × 1.5"对照当前宽度，base 被污染后阈值失真，"150% 一触即发"。

## 4. 实现二（现行修复）

核心变更：**用真实缩放比判定是否冻结，并在非冻结态让 base 跟随视口、可回落**。

```javascript
const ZOOM_FREEZE_RATIO = 1.5

const syncZoomBase = () => {
  const root = document.documentElement
  const zoom = window.outerWidth / window.innerWidth
  if (zoom > ZOOM_FREEZE_RATIO) return
  root.style.setProperty('--zoom-base', `${window.innerWidth}px`)
}
```

### 行为对照（视口 = window 宽 1440px）

| 场景 | zoom | 行为 | base |
| --- | --- | --- | --- |
| 100% | 1.00 | 正常自适应 | 1440px |
| 150% | 1.50 | 正常自适应（临界） | 960px |
| 151%+ | > 1.5 | **冻结**：不更新 base，min-width 生效，纯放大+横向滚动 | 960px |
| 50%（缩小） | 0.50 | base 跟随视口变大 | 2880px |
| 50% → 100% | 1.00 | base 回落，布局恢复居中（修复点） | 1440px |
| 100% → 250% | 2.50 | 直接冻结 | 1440px |
| 250% → 100% | 1.00 | base 回落，布局恢复（修复点） | 1440px |

### 为什么修复有效

- `zoom` 由 `outerWidth / innerWidth` 计算，缩放时外宽不变，比值精确反映真实缩放；
- `zoom <= 1.5` 时无条件把 base 更新为当前 `innerWidth`，缩小态把 base 撑大后，回到 100% 会被重新覆盖为 1440px，污染立即清除；
- `zoom > 1.5` 时直接 `return`，base 停留在进入冻结前的最后一个非冻结值（如 960px），后续放大不再重排、只放大 + 横向滚动，阈值锚定在 150% 附近。

## 6. 验证方法

无头 Chrome + CDP，通过 `Object.defineProperty` 覆写 `window.outerWidth/innerWidth` 并派发 `resize` 事件，逐场景断言 `--zoom-base`，涵盖：100%/150%/151%/160%/200%/250%、缩小、以及缩小后回落、放大后回落等 12 组序列，全数通过后清理临时进程。

```text
100%            → base = 1440px  ✓
150%            → base = 960px   ✓
151% +          → base = 960px（冻结） ✓
50%（缩小）      → base = 2880px  ✓
50% → 100%      → base = 1440px  ✓
100% → 250%     → base = 1440px（冻结） ✓
250% → 100%     → base = 1440px  ✓
```
