## 3. 转码流程与代码位置

### 3.1 ffmpeg 调用位置

`work-service/internal/work/transcode.go`

| 函数 | 行号 | 作用 |
|---|---|---|
| `Transcode()` | 61-90 | 视频转 HLS 分片 |
| `ExtractAudio()` | 92-102 | 提取音频 MP3 |
| `GetDuration()` | 48-58 | ffprobe 读时长 |

转码参数（当前为**纯软件编码**）：

```go
"-vf", "scale=" + scale,
"-c:v", "libx264", "-preset", "veryfast", "-crf", crf,
"-c:a", "aac", "-b:a", "128k",
"-f", "hls", "-hls_time", "6", ...
```

档位：`1080p → crf20/1920px`，`720p → crf22/1280px`，默认 `→ crf23/854px`。

调度链：`pipeline.go` 的 `Start()` 订阅 NATS `TopicVideoProcess` → `doTranscode()` 下载源文件 → 转三档 → 上传 MinIO。

### 3.2 转码产物对比

## 4. 决策：为什么继续用软件编码（libx264）

### 4.1 现场实测（229 秒真实视频，720p 档）

| 指标 | 软件 libx264 (crf22) | 硬件 VAAPI (CQP22) | 结论 |
|---|---|---|---|
| 编码耗时 | 21.7 s (12.6x 实时) | 13.9 s (19.9x 实时) | 硬件快 ~1.5x |
| 产物体积 | **4.6 MB** | 8.2 MB | **软件小 1.8 倍** |
| 平均码率 | **168 kbps** | 299 kbps | **软件省一半带宽** |
| 换电脑兼容 | 100%（任意 ffmpeg） | 依赖 GPU/驱动 | 软件零风险 |

*注：本机 AMD Lucienne 核显 VAAPI 仅支持 CQP/CBR/VBR，不支持 ICQ 智能码率控制。*

### 4.2 行业背景（联网核实）

- **VOD 点播场景：软件编码占主流 82%**（Streaming Learning Center / Bitmovin 2021 调查）。
- vBench（哥伦比亚大学）评测原话："GPU 是直播转码的明显赢家，但在点播归档上牺牲压缩率和画质。"
- 小破站/抖音/YouTube/Netflix 的**点播内容走软件编码**（x264/x265/SVT-AV1），因为点播一次编码多次播放，编码效率（体积/带宽）是长期成本。
- **硬件编码的"正宗"主场是直播/低延迟实时转码**（斗鱼、Twitch、视频会议），追求速度优先，画质码率效率不是首要指标。
- 唯一例外：YouTube 用自研 ASIC（Argos）编码点播视频，但那是**专门为达到软件编码质量而设计的定制芯片**（混合硬件/软件 + 固件迭代），与消费级 GPU 附带的 NVENC/VAAPI/QSV（为实时而设计）完全不同。

### 4.3 决策结论

| 选项 | 是否采纳 | 原因 |
|---|---|---|
| 现状：软件 libx264 | ✅ **采纳** | 体积小、带宽省、换电脑零依赖，符合 VOD 行业主流 |
| VAAPI 硬件加速 | ❌ 不做主选 | 快 1.5x 但体积大 1.8x，带宽翻倍，无性能瓶颈可破 |
| 硬件作为可选开关 | 将来可考虑 | 若未来做直播/实时转码再引入 |

**一句话**：点播场景最合适、最主流的做法是软件编码；硬编是直播场景的"正宗"。

## 5. 决策：音频从 WAV 迁移到 MP3

### 5.1 背景

- 原 `ExtractAudio` 输出 **PCM WAV 16kHz 单声道**，13 个视频音频合计 **52 MB**，占 MinIO 总存储的 40%+。
- 计划弃用本地 Whisper，改用 **Cloudflare Workers AI**（`@cf/openai/whisper`）。

### 5.2 核实：Cloudflare Whisper 支持什么格式？

- **支持 MP3、MP4、WAV、WebM** 等多种音频格式（官方教程示例即使用 `.mp3`）。
- **25 MB 单文件上限**：WAV 4 分钟约 40 MB 会超限，而 MP3 128kbps 仅约 4 MB——转 MP3 不是妥协而是必需。
- 注意：有用户反馈 4 分 28 秒的 MP3 偶现报错（Cloudflare 社区 #662925），需对最长视频实测。

### 5.3 代码改动

`transcode.go ExtractAudio()`：

```go
// 旧：PCM WAV
"-vn", "-acodec", "pcm_s16le", "-ar", "16000", "-ac", "1"

// 新：MP3（Cloudflare Whisper 兼容）
"-vn", "-acodec", "libmp3lame", "-b:a", "64k", "-ar", "44100", "-ac", "1"
```

`pipeline.go` 同步：key 从 `audio.wav` → `audio.mp3`，content-type `audio/wav` → `audio/mpeg`。

### 5.4 存储收益

| 指标 | 之前 (WAV) | 现在 (MP3) | 节省 |
|---|---|---|---|
| 音频合计 | 52 MB | **14 MB** | **73%** |
| MinIO 总占用 | 193 MB | **154 MB** | 20% |

最长视频 MP3 = 2.9 MB，远低于 Whisper 25 MB 上限。

## 6. MinIO 存储现状（154 MB）

| 类型 | 大小 | 占比 |
|---|---|---|
| 转码分片 (720p HLS) | 71.8 MB | 48% |
| 源视频 (H.264 mp4) | 64.0 MB | 43% |
| 音频 (MP3) | 13.1 MB | 9% |

**结论**：转码分片 + 源视频占 91%。音频已不是大头。

### 潜在优化方向（未实施）

1. **补全 1080p / 480p 多档转码**：当前只有 720p 成功（1080p/480p 因 AMD VAAPI/源尺寸被跳过），源 FPS 支持完整。
2. **分片 CRF 调优**：crf22 → 26 可再省 30-40% 分片体积。
3. **源视频与分片二选一**：源本就是 H.264，若接受直接播 MP4 可省掉 72 MB 分片。
