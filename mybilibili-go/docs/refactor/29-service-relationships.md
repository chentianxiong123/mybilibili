# 服务关系与前后端嵌入策略

## 1. 谁嵌前端，谁不嵌

| 服务 | 嵌前端 | 原因 |
|------|--------|------|
| **Core 胖单体** | ✅ go:embed | 浏览器直接访问，单二进制部署 |
| **Media 服务** | ❌ 不嵌 | 纯后台处理，无用户界面，仅工作站 |
| **Live 服务** | ❌ 不嵌 | 独立 WS 端口，只做信令转发 |

**只有 Core 胖单体嵌前端，因为只有 Core 是给浏览器直接访问的。** Media 和 Live 没有前端页面，不需要 go:embed。

---

## 2. 服务间通信

```
                      ┌──────────────────────┐
                      │    浏览器/APP         │
                      └──────────┬───────────┘
                                 │
                      ┌──────────▼───────────┐
                      │  Core 胖单体          │
                      │  (gRPC + HTTP + SSE)  │
                      │  (go:embed 前端)       │
                      └────┬──────┬──────┬───┘
                           │      │      │
           ┌───────────────┘      │      └───────────────┐
           │                      │                      │
     ┌─────▼──────┐         ┌─────▼──────┐         ┌─────▼──────┐
     │  NATS MQ   │         │  gRPC 回调 │         │  用户直连   │
     └─────┬──────┘         └────────────┘         └─────┬──────┘
           │                                              │
     ┌─────▼──────┐                                 ┌─────▼──────┐
     │ Media 服务  │                                 │ Live 服务   │
     │ (转码/字幕)  │                                 │ (WS 信令)    │
     │ (仅工作站)   │                                 │ (盒子/工作站) │
     └────────────┘                                 └────────────┘
```

**通信原则：**
- **Core → Media**：单向 MQ 任务，不直接调
- **Media 完成后**：回调 Core 的 HTTP 接口（更新状态 + 推 SSE 进度）
- **Live**：用户直连 WS，不进 Core；需要时调 Core 的 gRPC 查数据
- **Core 不主动调 Live**

---

## 3. 三个端共享同一套后端

```
Web 端：   Vue 3 + TailwindCSS（独立，SSR 可加 Nuxt）
APP 端：   Flutter（Dart，原生性能）
桌面端：   Flutter（一套代码，Windows/macOS/Linux）
         │
         └──── 共用 Core 胖单体的 API / SSE / WS
```

- 后端不变，三端各自独立 UI
- 共享 `packages/shared`（API 类型定义，从 proto 生成）
- 不共享 UI 组件（各端 UI 差异大，强行共享两头不讨好）

---

## 4. 部署维度

| 维度 | 盒子（1GB） | 工作站（64GB） |
|------|------------|---------------|
| Core 胖单体 | ✅ 跑（20MB） | ✅ 跑（多副本） |
| Media 服务 | ❌ 不跑（无 FFmpeg） | ✅ 跑（有 GPU） |
| Live 服务 | ✅ 跑（轻 WS） | ✅ 跑 |
| PG/Redis/NATS/MinIO | ❌ 不跑 | ✅ 跑 |
| 嵌前端 | ✅ 浏览器直接访问 | ✅ 同 |
| 总内存 | ~60MB | ~500MB |

**盒子和工作站用同一套 Core 二进制，只是启动配置不同**（盒子连工作站的基础设施，或无工作站时降级为 SQLite + 内存缓存）。

---

## 5. 一句话总结

**Core 胖单体嵌前端、对外暴露；Media 和 Live 独立不嵌前端、Core 不主动调它们。** 三端（Web/APP/桌面）共用同一套后端 API，各自独立 UI。
